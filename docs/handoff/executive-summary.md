# ccmem —— 接手入口（10 行）

> 全文在 `docs/handoff/handoff.md`。本页只负责让你**不在前十分钟里做错事**。
> 本页不写 commit SHA、不记 `main` 与 `origin/main` 的相对位置 —— 提交本页就会移动 HEAD，那个数字随时在变。

1. **先跑 `git status` + `git log --oneline -15`，自己确认状态。** 硬禁令：**不要 push**；**删分支/worktree 先问**；**plist 与配置内容不打印、不落盘**。
2. **没有已知待修的产品 bug。** 未修的是**三条测试抖动**：`waitForDaemonLock` 的 3s 上限（最高频）、`readDaemonLock` 遇 SQLITE_BUSY 直接抛、`plist-drift` T2/T13。见 handoff Ⅹ 与 Ⅶ。
3. **⚠️ 套件不是稳定绿：两个快照分别是 18/112 ≈ 16% 和 6/48 = 12.5% 的跑会红。** 看到红**先去 Ⅹ 对号入座**，别当成自己引入的回归。
4. **要动那三条，先读 Ⅹ 再动手** —— 仪器写法、正面对照、判据、需要的跑数都在里面，**别重新设计**。⚠️ 但 Ⅹ 里"按行号归并计数"的老账已作废：**按行号计数前先逐条分类失败模式**。
5. **验证间歇性修复必须用确定性变异判据**（修复前该变异逼出红、修复后同一变异全绿），**不许用"跑 N 次全绿"**。
6. **变异实验必须复现目标的真实条件，且仪器要自证开火。** 两次"单跑变异 0/N"因缺并发维度而无效；另一次 seam 被嵌套调用耗掉引信、以及 seam 静默失效，都读出过假绿。
7. **探针：n=60 / 目标 ~300，不要改探针代码；`openai_timeout_ms` 要改先出计划。** 数字**每轮重算**，别照抄任何版本。
8. **🔴 取数前先比对采样窗口与你自己的重活时段** —— **Ⅰ 里有污染窗口清单，逐条对**。曾把 `P(ms≤800)` 从 85% 压到 50%，差点读成"信号变强"。
9. **人类裁决（handoff Ⅵ）不得静默推翻**，其中 Ⅵ.10：**SDD workspace 一律不删** —— SDD skill 最后一步会让你删，**别听它的**。
10. **成本会失控**：单轮 $40–160，几乎全花在重复跑套件上。**开工前 `/compact`；要取证就一次跑够 32–48 次**，别 8 次一批反复试。**生产改动别省 code review，它连续两轮都抓到自查漏掉的东西。**
