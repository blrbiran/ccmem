# ccmem Stop Transcript Tail Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development.

**Goal:** Bound Stop-hook transcript memory by reading at most the final 2 MiB while preserving the exact byte window for asynchronous summarization.

**Architecture:** Add a byte-bounded JSONL transcript-window reader that starts at a complete line boundary and uses the existing agent normalizers. Stop-hook statistics and inferences consume the window entries once; the queued summarize task stores its byte range so the daemon later reads the same snapshot instead of re-reading the whole transcript. Existing queued tasks without a byte range retain current behavior.

**Tech Stack:** Node.js ESM, `node:fs`, built-in test runner.

**Spec:** `../orca_archived_files/issue-20261023.md` issue #395; detailed design memo `../Orca/.superpowers/sdd/plan/design-395-hooks.md`.

## Global Constraints

- Maximum raw transcript window: 2 MiB.
- The window begins after the first newline when the file is larger than the limit; do not parse a partial JSONL record.
- The byte range ends at the file size observed when Stop runs; later appends are excluded from the queued summary.
- `last_message_seq` must retain its existing full-transcript meaning so an already-running daemon that does not understand `transcript_window` still summarizes the same prefix; collect total counts in a streaming pass without retaining the full transcript.
- `transcript_excerpt_max` still controls the character cap after parsing.
- No production user data or daemon restart is part of the implementation test.

## Review Focus

- An exactly 2 MiB file starts at byte 0 and remains fully parseable.
- A file larger than 2 MiB discards the partial first JSONL line and returns only valid entries.
- A UTF-8 multibyte character at the byte boundary cannot create replacement text in parsed records.
- OMP parsing remains bounded even when the active branch's parent is outside the retained window.
- Appends after Stop do not enter the queued summary; the task reads the original `{startByte,endByte}` range.
- Legacy summarize task payloads without byte-range metadata keep the prior full-transcript behavior.

## Tasks

### Task 1: Bounded transcript window

- Add tests proving that a large prefix is omitted, the last complete assistant entry is retained, and the bytes read do not exceed 2 MiB.
- Implement `parseTranscriptWindow(path, agent, maxBytes)` returning normalized entries and `{startByte,endByte}` metadata.
- Make `handleStop` use that single window read for stats, feedback inference, L2.5 probe, and enqueue metadata.

### Task 2: Snapshot-consistent summarize task

- Add an integration test proving a queued task reads only its recorded byte range even when the transcript later grows.
- Add two successive Stop snapshots where the later endByte is greater but the retained-entry count is smaller; the older task must be superseded and must not replace newer session state.
- Put `snapshot_observed_at` in the Stop payload and preserve it through retries; later Stop snapshots supersede old retries using that stable timestamp (legacy payloads fall back to `last_message_seq`).
- Avoid the existing `(session_id,last_message_seq)` unique-index trap: when a newer Stop arrives, mark older queued/running rows for that session superseded before inserting the new snapshot, including when retained counts are equal. Retries preserve the original `snapshot_observed_at`.
- Replay parses exactly `[startByte,endByte)` and uses the same `completeLinesOnly` rule as Stop. Short/incomplete snapshots are marked unusable and skipped/audited, never summarized as valid prefixes.
- Add direct range-reader assertions for an in-range entry versus appended out-of-range data, plus OMP branch-switch behavior that exposes the actual `endByte` boundary.
- Update `runSummarizePending` to read/parse the stored range when present and preserve the legacy full-file path for old payloads.
- Run the affected Stop and summarize tests, then the full `npm test` suite; this repo has no build script.
