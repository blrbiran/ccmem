Hermes Agent 的记忆机制是一套旨在让 AI 拥有持久、可进化“记忆”的分层系统。它并非简单的对话历史记录，而是通过一套设计巧妙的“自学习闭环”，让 Agent 能跨会话积累经验、沉淀技能，甚至实现自我进化。其运作核心可概括为：

```mermaid

    subgraph A [记忆系统 (Memory)]
        direction LR
        A1[内置记忆<br>MEMORY.md / USER.md] --> A2[会话存档<br>SQLite FTS5]
        A2 --> A3[技能记忆<br>Skills Markdown]
    end

    subgraph B [反思与进化引擎]
        B1[Nudge Engine<br>主动反思]
    end

    A --> B
    B --> A
```

### 🧠 核心：四层记忆架构

为了平衡成本与效率，Hermes 将记忆分为了四层。

*   **第一层：热记忆**：以 `MEMORY.md` 和 `USER.md` 文件为核心，存储 Agent 对当前环境和用户的最高价值认知，始终在上下文中且即时生效。系统会为其设定严格的容量上限（如 2200 字符），迫使 Agent 对信息进行提炼和压缩。

*   **第二层：会话存档**：基于 SQLite 和 FTS5 全文搜索引擎，记录所有历史交互，形成“冷记忆”库。仅在 Agent 需要回忆历史细节（如“上次那个 bug 是怎么解决的？”）时，才会调用工具去检索。

*   **第三层：技能记忆**：将成功完成任务的方法论沉淀为可复用的结构化模板，属于“过程性记忆”，存储在 `~/.hermes/skills/` 目录中。

*   **第四层：外部记忆提供者**：通过 Mem0、Tablestore 等插件接口，接入外部向量数据库。用于处理海量记忆的语义检索和实体解析，并能实现跨会话、跨 Agent 的记忆共享。

### ⚙️ 关键机制：记忆如何运作

除了分层存储，Hermes 的记忆系统还通过以下机制保证其有效性：

*   **主动反思**：Nudge Engine 会根据配置定期触发 Agent 进行反思，主动从会话存档中提取、总结新的记忆并写入 `MEMORY.md`。
*   **反馈闭环**：每次任务后分析执行轨迹，自动提炼经验规则更新记忆；并根据用户的评分等反馈，动态调整记忆权重和优先级。
*   **工作流程**：整个流程在会话中不断循环：会话开始加载热记忆和预取相关记忆 → Agent 主动判断并写入记忆 → 后台预处理下一轮所需记忆。

总的来说，Hermes Agent 的记忆机制是一个从“即时上下文”到“历史档案”，再到“可复用技能”和“云端持久化”的完整认知架构。它让 AI Agent 从只会一问一答的工具，真正进化为一个能持续学习、越用越懂你的智能伙伴。
